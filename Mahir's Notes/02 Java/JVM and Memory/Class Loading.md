# Class Loading

## Why It Matters

Explains `NoClassDefFoundError` vs `ClassNotFoundException`, why the holder singleton is thread-safe, and how frameworks and app servers isolate classes.

## The Three Phases

```mermaid
flowchart LR
    A[Loading<br/>read bytecode] --> B[Linking]
    B --> B1[Verification<br/>bytecode is safe]
    B1 --> B2[Preparation<br/>statics get defaults]
    B2 --> B3[Resolution<br/>symbolic refs resolved]
    B3 --> C[Initialization<br/>static init + static blocks]
```

**Preparation vs Initialization** is a classic question: preparation assigns *default* values (`0`, `null`, `false`); initialization runs the actual assignments and `static {}` blocks.

```java
static int x = 5;
// after preparation:    x == 0
// after initialization: x == 5
```

## When Initialization Happens

Triggered by:
- Creating an instance (`new`)
- Accessing a **non-final** static field or method
- Reflection (`Class.forName`)
- Initialising a subclass (triggers the superclass first)

**Not** triggered by:
- Accessing a `static final` compile-time constant (inlined at compile time)
- Declaring a variable of the type
- `ClassName.class`

This is precisely why the **Bill Pugh holder singleton** works: the holder class isn't initialised until `Holder.INSTANCE` is first read, and the JVM guarantees class initialisation is thread-safe.

## The Delegation Hierarchy

```
Bootstrap  (native, java.base)
    ↑ delegates up
Platform   (formerly Extension)
    ↑
Application (classpath)
    ↑
Custom classloaders
```

A classloader **asks its parent first**, and only loads the class itself if the parent fails.

**Why:** security and consistency. Without delegation, someone could place a rogue `java.lang.String` on the classpath and override the real one.

## Class Identity

A class is identified by **fully-qualified name + classloader**. The same `.class` file loaded by two different classloaders produces two distinct, incompatible types.

```java
// Throws ClassCastException even though the names match
Object o = loaderA.loadClass("com.Foo").newInstance();
com.Foo f = (com.Foo) o;   // loaded by loaderB
```

This is the root cause of confusing errors in app servers and OSGi, and the mechanism that lets two web apps use different versions of the same library.

## ClassNotFoundException vs NoClassDefFoundError

| | ClassNotFoundException | NoClassDefFoundError |
|---|---|---|
| Type | Checked exception | Error |
| When | Explicit dynamic load (`Class.forName`, `loadClass`) fails | Class was present at compile time but is missing/failed to initialise at runtime |
| Common cause | Missing JAR, wrong name string | Version mismatch, or a **previous** static-initialiser failure |

**The subtle case:** if a static initialiser throws, the class is marked erroneous. The first access throws `ExceptionInInitializerError`; every *subsequent* access throws `NoClassDefFoundError`. Engineers chase the wrong error because the real cause was the first failure.

## Custom Classloaders

Extend `ClassLoader` and override `findClass` (not `loadClass`, which implements delegation). Used for plugin systems, hot reloading, and encrypted or generated bytecode.

```java
protected Class<?> findClass(String name) throws ClassNotFoundException {
    byte[] bytes = loadBytes(name);
    return defineClass(name, bytes, 0, bytes.length);
}
```

## Common Questions

- *Why does the holder singleton not need synchronisation?* — JVM-guaranteed thread-safe class initialisation, triggered lazily.
- *Why delegate to the parent first?* — prevents core-class spoofing and keeps types consistent.
- *Can two classes have the same fully-qualified name?* — yes, if loaded by different classloaders; they are distinct types.

## Common Mistakes

- Overriding `loadClass` instead of `findClass` and accidentally breaking delegation
- Assuming `static final` constants trigger initialisation (they don't — they're inlined)
- Not recognising `NoClassDefFoundError` as a symptom of an earlier initialiser failure
- Classloader leaks in redeployed web apps (a static field holding a reference pins the whole loader)
