## PROCESSING WORKFLOW

Process EACH enabled company independently. If one fails, continue to next.

### STEP 1: NAVIGATION & RETRY LOGIC

1. Navigate to `job_board_url`
2. Check if filters from `comments` field are applied in UI
3. If filters NOT applied, apply them manually using UI controls
4. check if date sorting option is available, if yes then sort by most recent
5. If page fails to load (timeout/error/CAPTCHA):
   - Wait 5 seconds
   - Retry navigation
   - Repeat up to `max_retries` times
   - If all retries fail: log FAILURE and move to next company

### STEP 2: SCAN ALL JOB TITLES

Scan all visible job listings on the page. Handle pagination if present (process maximum 50 jobs per company).

### STEP 3: FIRST-PASS TITLE FILTERING

**EXCLUDE** jobs with titles containing ANY of these terms:
- **Seniority**: "Staff Engineer", "Principal", "Senior Staff", "Sr. Staff",  "Lead", "Senior" (when combined with specific roles like "Senior Manager")
- **Management**: "Manager", "Engineering Manager", "Director", "VP", "Head of", "Chief"
- **QA/Testing**: "QA", "Quality Assurance", "Test", "Testing", "SDET", "Automation Test", "Test Engineer"
- **Mobile**: "iOS", "Android", "Mobile Developer", "Mobile Engineer", "React Native"
- **Other**: "Architect", "Solution Architect", "Intern", "Internship", "Junior", "Fresher", "Trainee", "Graduate Engineer"
- **High Experience**: "5+ years", "6+ years", "7+ years", "8+ years", "10+ years" (in title)

**INCLUDE** titles matching (not an exhaustive list):
- Exact: "Software Engineer II", "SDE-2", "SDE II", "MTS-2", "Software Engineer 2", "MTS"
- General: "Software Engineer", "SDE", "Backend Engineer", "Full Stack Engineer", "Fullstack Engineer"
- Experience indicators: "3-5 years", "3-4 years", "4-5 years" in title

### STEP 4: LOCATION FILTERING

**EXCLUDE** if location does NOT match ANY of:
- "Bangalore"
- "Bengaluru"
- "Remote"
- "Hybrid" (if mentions Bangalore/Bengaluru)
- "Work from Home"
- "WFH"

### STEP 5: DEDUPLICATION CHECK

For each job passing title + location filters:
1. **Attempt to extract job URL** without clicking:
   - Inspect link element (href attribute)
   - Check data attributes (data-url, data-job-id)
   - If URL accessible: calculate SHA-256 hash
2. **If URL not accessible without click**:
   - Click to open job
   - Extract URL from browser address bar
   - Calculate SHA-256 hash
3. **Compare hash** against hashes array
4. **If hash EXISTS**: 
   - Close job (if opened)
   - Skip to next job
   - Increment skipped count
5. **If hash is NEW**: 
   - If not already open, click to open
   - Proceed to STEP 6 (extract details)

### STEP 6: EXTRACT JOB DETAILS

For each new job:
1. Click to open full job description
2. Extract the following:
   - **job_id**: Company's internal job ID (from URL or page - NOT your custom ID)
   - **title**: Exact job title
   - **url**: Full job URL
   - **location**: Location text
   - **department**: Department/team name (if available)
   - **experience_text**: Exact experience requirement text from JD
   - **posted_date_text**: When job was posted (if available)
   - **salary_text**: Salary/compensation info (if mentioned in JD)

### STEP 7: CALCULATE DERIVED FIELDS

1. **job_url_hash**: SHA-256 hash of job URL (64 characters)
2. **display_id**: Format as `{COMPANY_ABBREVIATION}-{3_DIGIT_COUNTER}`
   - PhonePe → PHO-001, PHO-002
   - Flipkart → FLP-001, FLP-002
   - Microsoft → MST-001, MST-002
3. **is_remote**: `true` if location contains "Remote", "WFH", or "Work from Home", else `false`
4. **role_category**: Auto-detect from title and JD:
   - "backend" if mentions: Backend, Server-side, API, Microservices, Java, Spring
   - "frontend" if mentions: Frontend, UI, React, Angular, Vue
   - "fullstack" if mentions: Full Stack, Fullstack, Full-stack
   - "devops" if mentions: DevOps, SRE, Infrastructure, Platform
   - "general" if unclear
5. **days_since_posted**: 
   - If posted_date_text = "today" or "Today" → 0
   - If posted_date_text = "yesterday" or "1 day ago" → 1
   - If posted_date_text = "X days ago" → extract number X
   - If posted_date_text = "X weeks ago" → X * 7
   - If posted_date_text = "X months ago" → X * 30
   - If posted_date_text unavailable → 999
6. **estimated_date**: `false` if date extracted from JD, `true` if using 999 fallback

### STEP 8: MATCH ANALYSIS

1. **Extract required skills** from JD
2. **Compare with candidate skills** from INPUT 1
3. **Calculate match_percent** (0-100):
   - **70% weight**: Skills overlap
     - Count matched skills vs total required skills
     - Formula: (matched_skills / total_required_skills) * 70
   - **30% weight**: Experience alignment
     - If required years ≤ 5: full 30 points
     - If required years > 5: scale down (e.g., 6 years req → 20 points, 7 years → 10 points)
4. **skills_matched**: Comma-separated list of matched skills
5. **skills_missing**: Comma-separated list of required skills NOT in candidate profile
6. **experience_match**: 
   - `true` if required years ≤ 5 OR required years ≤ candidate's years + 1
   - `false` otherwise
7. **reasoning**: 1-2 sentences explaining match score and key strengths/concerns

### STEP 9: FILTERING OUTPUT

**Only include jobs where:**
- `experience_match = true`
- `location` is in allowed list

### STEP 10: SET DEFAULT FIELDS

For each job added to results:
- `application_status`: "not_applied"
- `is_starred`: false
- `status`: "new"
- `timestamp`: Current ISO 8601 timestamp

## LOGGING REQUIREMENTS

Create **ONE log entry per company** with:

### log_type
- `"success"`: Processed successfully, jobs found or not
- `"failure"`: Could not access job board after all retries
- `"warning"`: Partial success (e.g., some jobs failed to load)

### status_code
- `"OK"`: Processed successfully on first attempt
- `"RETRY_SUCCESS"`: Failed initially, succeeded after retry (mention which retry: 1, 2, or 3)
- `"TIMEOUT"`: Page didn't load after max_retries
- `"CAPTCHA"`: CAPTCHA detected, cannot proceed
- `"ACCESS_DENIED"`: 403/blocked/access denied
- `"RATE_LIMITED"`: Rate limiting detected
- `"MANUAL_SCAN_NEEDED"`: UI too complex/broken, needs manual intervention

### Other fields
- `jobs_scanned`: Total job listings seen (before any filtering)
- `jobs_skipped_duplicate`: Count of jobs skipped due to hash match
- `jobs_matched`: Jobs meeting all criteria (in results array)
- `retry_attempted`: `true` if any retry was needed, `false` otherwise
- `retry_count`: Number of retries performed (0 if first attempt succeeded)
- `api_discovered`: If underlying API found, put URL here; else empty string
- `message`: Human-readable summary, e.g., "Scanned 25 jobs, skipped 8 duplicates, 4 matched"

## API DISCOVERY (OPTIONAL FALLBACK)

If job board UI is too complex, broken, or fails after retries:

1. Open browser DevTools → Network tab
2. Reload page and observe XHR/Fetch requests
3. Look for API endpoints returning job data (JSON responses)
4. Note the API URL in `api_discovered` field
5. Set `status_code = "MANUAL_SCAN_NEEDED"`
6. Continue to next company

Sort `results` array by:
1. **Primary**: `days_since_posted` ASC (newest first, unknown jobs at bottom)
2. **Secondary**: `match_percent` DESC (highest match first)
